# Deanery Statement App

Настольное Windows-приложение для сотрудников деканата и учебной части. Программа формирует ведомости по Excel-выгрузке из Moodle: читает студентов и проценты выполнения, определяет дисциплину по имени файла, применяет правила оценивания из PostgreSQL, учитывает несколько попыток и заполняет Word-шаблон ведомости.

Проект ориентирован на быстрый рабочий сценарий: выбрать выгрузку `.xlsx`, проверить предпросмотр, при необходимости отфильтровать студентов по индивидуальному номеру Moodle, заполнить реквизиты ведомости и получить готовый `.docx`, PDF или документ для печати.

## Кому подходит приложение

Приложение рассчитано на сотрудников, которые регулярно получают из Moodle Excel-выгрузки с результатами тестирования и должны быстро подготовить ведомость в утвержденном формате.

Подходит, если:

- Moodle выгружает результаты в `.xlsx`;
- в файле есть ФИО или раздельные колонки имени и фамилии;
- в файле есть процент выполнения;
- ведомость должна формироваться в Word;
- оценки считаются по процентной шкале;
- справочники и история должны храниться централизованно в PostgreSQL.

Не является прямой интеграцией с Moodle:

- приложение не подключается к Moodle по API;
- не скачивает отчеты самостоятельно;
- не отправляет результаты обратно в Moodle;
- не работает с `.xls`, `.csv` и Google Sheets напрямую.

## Как устроен основной процесс

1. Пользователь запускает приложение.
2. Выбирает режим ведомости: `ИФО` или `ОФО`.
3. Приложение загружает настройки из `config.ini`.
4. Приложение подключается к PostgreSQL и получает справочники.
5. Пользователь выбирает Excel-файл Moodle.
6. Приложение читает активный лист `.xlsx`, ищет заголовки и извлекает строки студентов.
7. По имени файла программа пытается определить дисциплину и подставить ее в поле предмета.
8. В предпросмотре показываются студенты, проценты, оценки, даты теста и примечания.
9. Пользователь уточняет реквизиты ведомости и фильтры.
10. При формировании программа выбирает итоговые строки студентов, рассчитывает оценки и заполняет Word-шаблон.
11. Готовый `.docx` сохраняется в выбранную папку.
12. Запись о ведомости сохраняется в таблицу `generated_statements`.
13. При необходимости пользователь экспортирует PDF, открывает файл, открывает папку или отправляет документ на печать.

## Режимы ИФО и ОФО

### ИФО

Режим ИФО предназначен для очно-заочной формы обучения. В этом режиме используются базовые поля:

- предмет;
- группа;
- специальность;
- преподаватель;
- индивидуальный номер Moodle;
- дата начала теста;
- флаг вывода процента в оценке.

По умолчанию для ИФО используется шаблон:

```text
app/templates/statement_template_ifo_diff.docx
```

Также в проекте есть шаблон:

```text
app/templates/statement_template_ifo_exam.docx
```

### ОФО

Режим ОФО предназначен для очной формы обучения. Помимо базовых полей, отображаются дополнительные реквизиты:

- семестр;
- учебный год;
- форма контроля;
- дата проведения;
- заведующий отделением.

По умолчанию для ОФО используется шаблон:

```text
app/templates/statement_template_ofo.docx
```

### Переключение режима

Режим можно сменить в главном окне. При переключении:

- меняется набор видимых полей;
- выбирается шаблон по умолчанию для нового режима;
- подгружается сохраненный пользовательский шаблон, если он был выбран ранее;
- текущий сформированный документ сбрасывается, чтобы не смешивать результат разных режимов.

## Системные требования

### Для запуска из исходного кода

- Windows 10 или новее.
- Python 3.11 рекомендуется. В текущем рабочем окружении используется Python 3.11.9.
- PostgreSQL с доступом к базе данных приложения.
- Пакеты из `requirements.txt`.

### Для PDF

Для экспорта PDF нужен один из вариантов:

- Microsoft Word на Windows;
- LibreOffice, доступный через команду `soffice` или `libreoffice`.

На Windows программа сначала пытается экспортировать PDF через Microsoft Word, затем через LibreOffice. На других системах используется LibreOffice.

### Для печати

Автоматическая отправка документа на печать реализована только для Windows. Используется стандартное действие Windows `print` для `.docx`.

### Для сборки установщика

- PyInstaller, уже указан в `requirements.txt`;
- Inno Setup для сборки установщика из `installer/setup.iss`.

## Быстрый старт для разработчика

Откройте PowerShell или командную строку в корне проекта.

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Если нужны тесты:

```bat
pip install -r requirements-dev.txt
```

Создайте рабочий конфиг:

```bat
copy config.example.ini config.ini
```

Создайте и заполните базу:

```bat
psql -U postgres -f sql\init_db.sql
psql -U postgres -d deanery_statement_app -f sql\seed_data.sql
```

Отредактируйте `config.ini` и укажите реальные параметры подключения к PostgreSQL.

Запустите приложение:

```bat
python -m app.main
```

Или через готовый Windows-скрипт:

```bat
run.bat
```

## Настройка PostgreSQL

### Что создают SQL-скрипты

`sql/init_db.sql`:

- создает базу `deanery_statement_app`, если ее еще нет;
- подключается к этой базе;
- создает таблицы справочников;
- создает таблицу правил оценивания;
- создает таблицу истории ведомостей;
- добавляет базовые семестры, учебные годы и формы контроля.

`sql/seed_data.sql`:

- добавляет начальную шкалу оценивания;
- добавляет демонстрационные предметы;
- добавляет демонстрационные группы;
- добавляет демонстрационные специальности;
- добавляет демонстрационных преподавателей;
- добавляет дополнительные значения справочников.

Повторный запуск скриптов допустим: для справочников используется `ON CONFLICT`, а правила оценивания обновляются по диапазону процентов.

### Таблицы

| Таблица | Назначение |
|---|---|
| `subjects` | Предметы |
| `student_groups` | Группы студентов |
| `specialties` | Специальности |
| `teachers` | Преподаватели |
| `semesters` | Семестры |
| `academic_years` | Учебные годы |
| `control_forms` | Формы контроля |
| `department_heads` | Заведующие отделением |
| `grade_rules` | Правила перевода процентов в оценки |
| `generated_statements` | История сформированных ведомостей |

### Пользователь базы данных

В `config.example.ini` указан пользователь `deanery_app`, но SQL-скрипты не создают роль PostgreSQL автоматически. Есть два варианта:

1. Использовать уже существующего пользователя PostgreSQL и указать его в `config.ini`.
2. Создать отдельного пользователя для приложения.

Пример создания отдельного пользователя:

```sql
CREATE USER deanery_app WITH PASSWORD 'change_me';
GRANT CONNECT ON DATABASE deanery_statement_app TO deanery_app;
```

После подключения к базе `deanery_statement_app` выдайте права на схему, таблицы и последовательности:

```sql
GRANT USAGE ON SCHEMA public TO deanery_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO deanery_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO deanery_app;

ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO deanery_app;

ALTER DEFAULT PRIVILEGES IN SCHEMA public
GRANT USAGE, SELECT ON SEQUENCES TO deanery_app;
```

Если `psql` не находится, добавьте папку `bin` PostgreSQL в `PATH` или запускайте команды через SQL Shell, установленный вместе с PostgreSQL.

## Конфигурация

Рабочий конфиг хранится в файле:

```text
config.ini
```

Пример лежит в:

```text
config.example.ini
```

Пример содержимого:

```ini
[database]
host=localhost
port=5432
user=deanery_app
password=change_me
database=deanery_statement_app

[app]
template_path=app/templates/statement_template_ifo_diff.docx
output_dir=output
keep_empty_rows=true

[excel]
header_search_rows=15
data_start_row=2
swap_first_last_names=true
```

### Секция `[database]`

| Параметр | Значение |
|---|---|
| `host` | Адрес PostgreSQL-сервера. Обычно `localhost`. |
| `port` | Порт PostgreSQL. Обычно `5432`. |
| `user` | Пользователь PostgreSQL. |
| `password` | Пароль пользователя. |
| `database` | Имя базы приложения. По умолчанию `deanery_statement_app`. |

### Секция `[app]`

| Параметр | Значение |
|---|---|
| `template_path` | Базовый путь к Word-шаблону для ИФО. Можно указать относительный или абсолютный путь. |
| `output_dir` | Папка, в которую по умолчанию предлагается сохранять ведомости. |
| `keep_empty_rows` | Если `true`, программа сохраняет пустые строки из таблицы шаблона, когда студентов меньше, чем строк в шаблоне. |

### Секция `[excel]`

| Параметр | Значение |
|---|---|
| `header_search_rows` | Сколько первых строк просматривать при поиске заголовков. |
| `data_start_row` | Минимальная строка начала данных. Фактически используется максимум из этого значения и строки после найденного заголовка. |
| `swap_first_last_names` | Зарезервированная настройка для порядка ФИО. В текущей логике итоговое ФИО собирается как `Фамилия Имя Отчество`. |

### Относительные пути

Относительные пути в `config.ini` считаются от корня приложения. Для исходного кода это папка репозитория. Для собранного EXE это папка рядом с исполняемым файлом.

### Безопасность конфигурации

`config.ini` не публикуется в Git, потому что может содержать реальные пароли, локальные пути и настройки конкретного рабочего места.

## Работа в интерфейсе

### 1. Выбор режима

При запуске появляется окно выбора режима:

- `ИФО`;
- `ОФО`.

Выбранный режим определяет набор полей и шаблон по умолчанию.

### 2. Загрузка справочников

После открытия главного окна приложение подключается к PostgreSQL и загружает:

- предметы;
- группы;
- специальности;
- преподавателей;
- семестры;
- учебные годы;
- формы контроля;
- заведующих отделением;
- правила оценивания.

Если подключение к БД не удалось, приложение покажет сообщение с рекомендацией проверить `config.ini`, доступность PostgreSQL и SQL-скрипты.

### 3. Выбор Excel-файла

Нажмите `Выбрать Excel-файл` и выберите выгрузку Moodle в формате `.xlsx`.

После загрузки приложение сообщает:

- строку заголовков;
- строку начала данных;
- количество найденных студентов;
- количество найденных индивидуальных номеров Moodle;
- наличие строк без индивидуального номера.

### 4. Проверка данных

В таблице предпросмотра отображаются колонки:

| Колонка | Что показывает |
|---|---|
| `№` | Номер в итоговой ведомости. Для попыток, которые не попадают в ведомость, номер пустой. |
| `ФИО студента` | Собранное ФИО. |
| `Инд. номер` | Индивидуальный номер Moodle. |
| `Тест начат` | Дата или дата-время начала теста. |
| `Процент` | Процент выполнения из Moodle. |
| `Оценка` | Расчетная оценка по правилам из БД. |
| `Примечание` | Информация о пересдачах и выборе лучшей попытки. |

Дату в колонке `Тест начат` можно исправить вручную. Это влияет на фильтр по дате и на отображение попыток в текущей сессии.

### 5. Заполнение реквизитов

Для ИФО обязательны:

- предмет;
- группа;
- специальность;
- преподаватель.

Для ОФО обязательны:

- предмет;
- группа;
- специальность;
- преподаватель;
- семестр;
- учебный год;
- форма контроля;
- дата проведения.

Поле `Зав. отделением` используется в шаблоне ОФО, если в шаблоне есть соответствующий placeholder.

### 6. Справочники

Значения можно выбрать из выпадающих списков или ввести вручную.

Кнопка `+` рядом с полем добавляет текущее значение в соответствующий справочник.

Кнопка `Справочники` открывает отдельное окно, где можно:

- искать значения;
- добавлять значения;
- переименовывать значения;
- удалять значения.

### 7. Настройка процентов в ведомости

Флаг `Показывать процент в оценке` управляет тем, как оценка попадет в Word.

Если флаг выключен:

```text
5 (отл)
```

Если флаг включен:

```text
5 (отл) - 95%
```

Для таблиц ОФО с раздельными колонками оценки программа записывает цифру и полное название оценки отдельно.

### 8. Формирование документа

Нажмите `Сформировать ведомость`.

Приложение предложит имя файла по шаблону:

```text
Ведомость_<предмет>_<группа>_<YYYYMMDD_HHMMSS>.docx
```

По умолчанию файл предлагается сохранить в папку `output`, если в `config.ini` не указана другая папка.

### 9. Действия с результатом

После формирования доступны:

- `Открыть документ`;
- `Экспорт в PDF`;
- `DOCX + PDF`;
- `Печать`;
- `Папка`;
- `История`.

## Формат Excel-файла Moodle

Поддерживается только `.xlsx`. Приложение читает активный лист книги.

### Обязательные данные

Для успешного чтения нужны:

- имя;
- фамилия;
- процент выполнения.

Отчество необязательно.

### Поддерживаемые заголовки имени

Для имени распознаются варианты:

- `имя`;
- `name`;
- `firstname`;
- `first name`;
- `given name`.

### Поддерживаемые заголовки фамилии

Для фамилии распознаются варианты:

- `фамилия`;
- `surname`;
- `lastname`;
- `last name`;
- `family name`.

### Поддерживаемые заголовки отчества

Для отчества распознаются:

- `отчество`;
- `middle name`;
- `middlename`.

### Поддерживаемые заголовки процента

Для процента распознаются:

- `процент`;
- `итоговый процент`;
- `общий процент`;
- `%`;
- `percentage`;
- `percent`;
- `процентная оценка`;
- `итоговая оценка (%)`.

Также программа считает колонку процентной, если в заголовке есть символ `%`, слово `процент` или `percent`.

### Индивидуальный номер Moodle

Для индивидуального номера распознаются:

- `индивидуальный номер`;
- `инд номер`;
- `инд. номер`;
- `individual number`;
- `id number`;
- `group code`.

Эта колонка необязательна, но полезна для фильтрации студентов по группе или потоку.

### Логин Moodle

Для логина распознаются:

- `логин`;
- `login`;
- `username`;
- `user name`.

Логин используется для надежного объединения нескольких попыток одного студента. Если логина нет, студент идентифицируется по ФИО и индивидуальному номеру Moodle.

### Дата начала теста

Для даты начала теста распознаются:

- `тест начат`;
- `начало теста`;
- `started`;
- `test started`;
- `started on`.

Дата нужна для фильтрации по дате и сортировки попыток.

### Форматы процентов

Программа принимает разные форматы процента:

| Значение в Excel | Как будет понято |
|---|---|
| `95` | 95% |
| `95.5` | 95.5% |
| `95,5` | 95.5% |
| `95%` | 95% |
| `0.95` | 95% |
| `19/20` | 95% |

Значения меньше 0 или больше 100 отбрасываются как некорректные. Если строка содержит посторонние символы, процент также не читается.

### Строки итоговой статистики

Приложение пропускает строки, похожие на сводную статистику Moodle. Например, строки с ключевыми словами:

- `общее`;
- `итог`;
- `среднее`;
- `total`;
- `average`;
- `summary`.

### Частые причины ошибки чтения Excel

- файл не `.xlsx`;
- файл открыт в другой программе и недоступен для чтения;
- в первых строках нет заголовков;
- заголовки сильно отличаются от поддерживаемых;
- нет колонки процента;
- проценты записаны как текст с лишними символами;
- строки студентов не содержат ФИО.

```text
хм_БД_ОФО_л26-Тестирование. Химия лето 2026-оценки.xlsx
```

В этом случае будет определено:

```text

```

Логика очищает имя файла от служебных слов и фрагментов:

- `оценки`;
- `оценка`;
- `тестирование`;
- `тест`;
- `лето`, `зима`, `весна`, `осень`;
- `офо`, `зфо`;
- `очно`, `заочно`;
- `экзамен`, `зачет`;
- `ведомость`;
- `итог`, `итоговая`;
- `moodle`;
- год вида `2026`;
- короткие служебные коды.

Если предмет определен неверно, его можно просто исправить вручную в форме.

## Фильтрация студентов

### Фильтр по индивидуальному номеру Moodle

В поле `Инд. номер Moodle` можно выбрать один или несколько номеров из файла.

Если ничего не выбрано, используется значение `Все из файла`.

Если в файле есть пустые индивидуальные номера, появляется вариант:

```text
Без инд. номера
```

### Автоматический фильтр по группе

Если пользователь не выбрал индивидуальный номер вручную, программа сравнивает поле `Группа` со списком индивидуальных номеров Moodle. Если значение группы совпадает с одним из номеров, приложение автоматически фильтрует студентов по этому номеру.

Это удобно, когда индивидуальный номер Moodle фактически совпадает с кодом группы.

### Фильтр по дате начала теста

Фильтр даты находится рядом с полем индивидуального номера Moodle. Значение `Все даты` отключает фильтр.

Дата нормализуется к виду:

```text
dd.MM.yyyy
```

Поддерживаются даты Moodle с русскими месяцами, ISO-формат и распространенные числовые форматы.

### Поиск и фильтр в предпросмотре

Поле поиска фильтрует видимые строки предпросмотра по тексту во всех колонках.

Фильтр оценки позволяет оставить только:

- все оценки;
- `5`;
- `4`;
- `3`;
- `2`.

Эти фильтры влияют на видимость строк в таблице предпросмотра. Итоговая ведомость формируется по выбранному набору студентов и правилам попыток, а не по скрытым строкам предпросмотра.

## Пересдачи и несколько попыток

Приложение группирует попытки одного студента.

Если в Excel есть логин Moodle, группировка идет по логину. Если логина нет, группировка идет по сочетанию:

```text
ФИО + индивидуальный номер Moodle
```

В итоговую ведомость попадает лучшая попытка.

Критерии выбора:

1. Максимальный процент.
2. При равном проценте более поздняя дата начала теста.
3. При равенстве даты более поздняя строка источника.

В предпросмотре видны все попытки. Для попыток добавляются примечания:

- `В ведомость: максимум из N попыток`;
- `Пересдача, не входит в ведомость`;
- `Попытка 1, не входит в ведомость`.

Если у студента одна попытка, примечание остается пустым.

## Правила оценивания

Оценка рассчитывается по таблице `grade_rules`.

Начальная шкала из `sql/seed_data.sql`:

| Процент | Оценка | Кратко | Полностью |
|---:|---:|---|---|
| 91-100 | 5 | `отл` | `отлично` |
| 81-90 | 4 | `хор` | `хорошо` |
| 71-80 | 3 | `удовл` | `удовлетворительно` |
| 0-70 | 2 | `неуд` | `неудовлетворительно` |

Границы диапазонов включительные.

Например:

- `70` дает `2`;
- `71` дает `3`;
- `90` дает `4`;
- `91` дает `5`.

Если процент пришел с десятичной частью и не попал в диапазон напрямую, приложение пробует округлить процент так же, как он показывается в ведомости.

### Редактирование правил

Кнопка `Оценки` открывает диалог правил оценивания.

В нем можно:

- добавить строку;
- удалить строку;
- изменить минимальный и максимальный процент;
- изменить номер оценки;
- изменить краткое и полное название.

При сохранении текущие правила в `grade_rules` заменяются новым набором.

Важно следить, чтобы диапазоны покрывали все нужные значения и не создавали неоднозначность. Приложение применяет первое подходящее правило из списка, отсортированного по номеру оценки и нижней границе процента.

## Word-шаблоны

Встроенные шаблоны находятся в:

```text
app/templates/
```

Файлы:

| Шаблон | Назначение |
|---|---|
| `statement_template_ifo_diff.docx` | ИФО, дифференцированный зачет |
| `statement_template_ifo_exam.docx` | ИФО, экзамен |
| `statement_template_ofo.docx` | ОФО |

Пользователь может выбрать другой `.docx` через кнопку `Шаблон`.

### Как сохраняется выбранный шаблон

Выбранные пути сохраняются в локальном файле:

```text
app_state.json
```

Для ИФО и ОФО используются разные ключи:

- `template_path_ifo`;
- `template_path_ofo`.

Это позволяет один раз выбрать нужные шаблоны и не выбирать их заново при каждом запуске.

### Placeholder-поля

Шаблон может содержать поля:

| Placeholder | Чем заменяется |
|---|---|
| `{{subject}}` | Предмет |
| `{{group}}` | Группа |
| `{{specialty}}` | Специальность |
| `{{teacher}}` | Преподаватель |
| `{{semester}}` | Семестр |
| `{{academic_year}}` | Учебный год |
| `{{control_form}}` | Форма контроля |
| `{{exam_date}}` | Дата проведения |
| `{{department_head}}` | Заведующий отделением |
| `{{students_count}}` | Количество студентов в итоговой ведомости |
| `{{grade_5_count}}` | Количество оценок `5` |
| `{{grade_4_count}}` | Количество оценок `4` |
| `{{grade_3_count}}` | Количество оценок `3` |
| `{{grade_2_count}}` | Количество оценок `2` |
| `{{absent_count}}` | Сейчас всегда `0` |

Также поддерживаются старые текстовые фрагменты:

- `По предмету: уточняется программой`;
- `Группа: уточняется программой`;
- `Специальность: уточняется программой`;
- `Преподаватель: уточняется программой`.

Они заменяются на заполненные значения.

### Таблица студентов

В шаблоне должна быть таблица студентов. Приложение ищет таблицу, где есть слова:

- `фамилия`;
- `оценка`;
- `подпись`.

Если такая таблица не найдена, используется первая таблица документа. Если таблиц нет, формирование завершится ошибкой.

В таблице должна быть строка заголовка, где есть `фамилия` и `оценка`.

Данные студентов начинаются со следующей строки. Если сразу после заголовка идет строка с подзаголовками `цифрой` или `прописью`, данные начинаются после нее.

### Таблица с общей оценкой

Если в строке таблицы меньше 5 ячеек, оценка записывается одной строкой:

```text
5 (отл)
```

Или при включенном проценте:

```text
5 (отл) - 95%
```

### Таблица с раздельной оценкой

Если в строке таблицы 5 ячеек или больше, приложение считает таблицу раздельной и пишет:

- в первую колонку - номер;
- во вторую - ФИО;
- в третью - оценку цифрой;
- в четвертую - оценку прописью;
- пятую оставляет пустой.

Это используется в шаблоне ОФО.

### Пустые строки

Параметр `keep_empty_rows=true` в `config.ini` сохраняет исходное количество пустых строк из шаблона, если студентов меньше, чем строк в таблице.

Если поставить `false`, таблица будет сокращаться до фактического количества студентов.

## PDF и печать

### Экспорт PDF

Кнопка `Экспорт в PDF` создает PDF рядом с текущим `.docx`.

Например:

```text
Ведомость_Химия_ЛД-101_20260707_143000.docx
Ведомость_Химия_ЛД-101_20260707_143000.pdf
```

На Windows используется такая последовательность:

1. Microsoft Word через COM.
2. LibreOffice, если Word недоступен или экспорт через Word завершился ошибкой.

На других системах используется LibreOffice.

### DOCX + PDF

Кнопка `DOCX + PDF` сначала формирует новый `.docx`, затем сразу экспортирует его в PDF.

### Печать

Кнопка `Печать` отправляет текущий `.docx` в стандартную печать Windows.

Если печать не работает, проверьте:

- установлен ли обработчик `.docx`;
- открывается ли документ в Word вручную;
- настроен ли принтер по умолчанию;
- не блокирует ли файл антивирус или политика безопасности.

## История ведомостей

После успешного формирования `.docx` в таблицу `generated_statements` сохраняются:

- предмет;
- группа;
- специальность;
- преподаватель;
- путь к исходному Excel-файлу;
- путь к итоговому Word-файлу;
- дата и время создания.

Кнопка `История` открывает последние записи.

В окне истории можно:

- обновить список;
- открыть выбранный документ;
- открыть папку выбранного документа.

История хранит пути к файлам. Если файл был перемещен или удален, запись останется в БД, но открыть документ по старому пути не получится.

## Сборка EXE

Перед сборкой убедитесь, что:

- установлены зависимости из `requirements.txt`;

```bat
build_exe.bat
```

Скрипт вызывает PyInstaller с параметрами:

Результат:

```text
dist/DeaneryStatementApp/DeaneryStatementApp.exe
```

Важно: если `config.ini` содержит реальные пароли, они попадут в папку сборки. Не передавайте такую сборку третьим лицам без проверки настроек.

## Частые проблемы

```bat
copy config.example.ini config.ini
```

### Не удается подключиться к PostgreSQL

Проверьте:

- запущен ли PostgreSQL;
- правильный ли `host`;
- правильный ли `port`;
- существует ли база `deanery_statement_app`;
- существует ли пользователь из `config.ini`;
- правильный ли пароль;
- есть ли у пользователя права на таблицы и последовательности.

Команды для проверки:

```bat
psql -U postgres -l
psql -U deanery_app -d deanery_statement_app
```

### Ошибка `relation does not exist`

Скорее всего, не выполнен `sql/init_db.sql` или приложение подключается не к той базе.

Запустите:

```bat
psql -U postgres -f sql\init_db.sql
psql -U postgres -d deanery_statement_app -f sql\seed_data.sql
```

### Excel-файл не читается

Проверьте:

- расширение файла `.xlsx`;
- файл не открыт в Excel в режиме блокировки;
- в первых строках есть заголовки;
- есть колонки имени, фамилии и процента;
- проценты находятся в диапазоне 0-100;
- в файле есть строки студентов.

Если заголовки находятся ниже, увеличьте:

```ini
[excel]
header_search_rows=30
```

### В ведомость попали не все студенты

Возможные причины:

- включен фильтр по индивидуальному номеру Moodle;
- группа совпала с индивидуальным номером Moodle и включился автоматический фильтр;
- включен фильтр по дате начала теста;
- часть строк не прочиталась из-за отсутствия ФИО или процента;
- несколько строк относятся к одному студенту, и в ведомость попала только лучшая попытка.

Проверьте таблицу предпросмотра и блок предупреждений.

### Оценка не считается

Причины:

- таблица `grade_rules` пустая;
- в правилах нет диапазона для нужного процента;
- диапазоны заданы некорректно;
- процент из Excel не удалось прочитать.

Откройте `Оценки` и проверьте шкалу.

### PDF не создается

Проверьте:

- установлен ли Microsoft Word;
- установлен ли LibreOffice;
- доступна ли команда `soffice` или `libreoffice`;
- не открыт ли PDF-файл в другой программе;
- есть ли права на запись в папку результата.

### Печать не работает

Проверьте:

- приложение запущено на Windows;
- `.docx` открывается вручную;
- установлен Word или другое приложение, связанное с `.docx`;
- настроен принтер по умолчанию.

### Шаблон не заполняется

Проверьте:

- файл шаблона существует;
- это именно `.docx`, а не `.doc`;
- в документе есть таблица студентов;
- в таблице есть заголовки с текстом `фамилия` и `оценка`;
- нужные placeholders написаны без ошибок;
- шаблон не поврежден.

### В собранной версии нет шаблонов или ресурсов

Пересоберите через:

```bat
build_exe.bat
```

Скрипт добавляет `app/templates` и `app/resources` в сборку. Если запускали PyInstaller вручную, проверьте параметры `--add-data`.
